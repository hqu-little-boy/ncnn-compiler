# Vulkan semantic, ABI, and execution-plan contracts

This document describes the Vulkan semantic subset, plan schema, C ABI, standalone host runtime, and the current opt-in `ncnn-compile` product artifact path. CPU remains the default backend; Vulkan is selected explicitly with `--backend=vulkan` and is fail-closed.

## Semantic pipeline and legality

`ncnn-mlir-opt --ncnn-vulkan-semantic-pipeline` consumes the strict NCNN-to-TOSA boundary: a model function with no remaining `ncnn.*` operations (an identity graph may contain no TOSA operations). The pipeline checks that boundary, runs the common TOSA-to-Linalg lowering, rejects residual TOSA, then runs `verify-vulkan-supported-model`.

The common lowering sequence is the upstream TOSA-to-Linalg pipeline, Linalg constant-transpose folding, nested TOSA-to-tensor and TOSA-to-arith conversion, canonicalization, and CSE. It uses `preferConv2DKernelLayoutHWCF=true`; this describes an intermediate Linalg layout, not a Vulkan storage-buffer layout. The CPU `ncnn-tosa-to-linalg-pipeline` uses the same helper and retains its CPU fusion and convolution-strategy passes in their established order.

The V1 verifier accepts only static FP32 copy/identity, elementwise ReLU (`max(input, 0.0)`), and same-shape elementwise Add. The lowered elementwise forms must have identity indexing maps and parallel iteration. Layout-only `linalg.transpose`, `tensor.expand_shape`, `tensor.collapse_shape`, `tensor.reshape`, `tensor.empty`, and `linalg.copy` are accepted when their tensor types satisfy the same static constraints. `tensor.reshape` additionally requires a constant rank-one index shape whose extents exactly match the static result type and whose element count preserves the source byte size. Every data tensor must be ranked FP32 with rank 1–4, positive static extents, checked byte size, and no more than the Vulkan 1.1 minimum storage-buffer range (128 MiB); the constant index shape operand is metadata, not a data buffer. Other operations, types, ranks, parameters, dynamic/zero extents, overflow, or oversized tensors fail; there is no CPU fallback. Device-specific limits remain a runtime responsibility and are not inferred by this semantic verifier.

The verifier reports `ncnn.name` and `ncnn.source_layer` recovered from the importer’s `NameLoc` carrier (`FileLineColLoc` filename `ncnn-layer`) when available, and falls back to operation attributes. Importing `.param/.bin` is not part of this pipeline command.

## GPU operation lowering

`ncnn-mlir-opt --ncnn-vulkan-v2-prepare-pipeline` consumes an ncnn-dialect model, runs NCNN-to-TOSA and the common TOSA-to-Linalg lowering, and rejects residual TOSA. It intentionally does not run the V1-only legality verifier because V2 adds convolution forms. `ncnn-mlir-opt --ncnn-vulkan-v2-pipeline` appends `lower-ncnn-vulkan-model`; for artifact-producing tests, the preparation pipeline and lowering pass can be run separately with `plan-path` set on the pass.

The lowering accepts exactly one model function. Its pointwise/layout path handles at most one compute operation per fixture: identity, `linalg.copy`, ReLU, same-shape Add, `linalg.transpose`, or a static layout-only reshape. Same-element-count reshape views may surround that operation. The Conv2D path handles one `linalg.conv_2d_nhwc_hwcf` plus the compiler-generated static input pad/layout views, broadcast bias initializer, and output crop/transpose scaffolding. Conv2D is restricted to batch one, groups one, static FP32 CHW input/output, constant FP32 weights, dilation one, 1x1 or 3x3 kernels, per-axis stride one or two, and zero padding of at most one element per side; 1x1 requires zero padding. Bias may be absent. Unsupported graph operations, multiple convolutions, dynamic extents/weights, unsupported convolution parameters, and multiple pointwise compute operations fail closed.

Each emitted `gpu.module` uses a Vulkan 1.1 / SPIR-V 1.0 target environment, a single `gpu.func` entry point, a `[64,1,1]` workgroup, and an explicit global-ID bounds guard. Pointwise and layout kernels use flattened FP32 StorageBuffers; transpose calculates row-major remapping and reshape preserves linear element order. The naive Conv2D kernel assigns each output element to one work item, accumulates in fixed kernel/input-channel order, applies zero padding and bias, reads OIHW source weights in HWCF physical order, and writes continuous CHW output. The schema-v1 plan records the weight and bias SHA-256 identities, descriptor bindings, layouts, workgroup, and static public I/O. The source tensor function is removed from the emitted device module.

The lowering emits GPU dialect IR and the execution plan, not SPIR-V bytes or a product host wrapper. Both the opt-in device tests and the product driver run MLIR’s `--test-vulkan-runner-pipeline`, extract `gpu.binary`, and validate SPIR-V. `lib/VulkanRuntime/` supplies the reusable host context; the V2 one-shot `vulkan_add_runner` remains only a test reference. `ncnn-compile --backend=vulkan` packages the validated plan and shader into a model DSO and emits the model lifecycle wrapper described below. The product compiler currently restricts this path to one static FP32 ReLU compute operation; broader V2 lowering capability does not imply broader product support.

## Model-instance C ABI

`include/ncnn-mlir/Vulkan/ModelABI.h` is a C-compatible declaration header. It defines ABI version 1, a fixed-width 32-bit `ncnn_vk_status`, `ncnn_vk_options` (`struct_size`, `abi_version`, `device_index`, and `flags`), `NCNN_VK_DEVICE_AUTO`, and the options initializer. The options structure is 16 bytes with four consecutive 32-bit fields; v1 requires a full v1-sized structure, accepts larger structures with the same ABI version while ignoring trailing fields, and requires `flags == 0`.

A model-specific header declares an opaque `<model>_vk_context` and these signatures:

```c
ncnn_vk_status <model>_vk_create(
    const ncnn_vk_options *options,
    <model>_vk_context **context,
    char *diagnostic,
    size_t diagnostic_capacity);

ncnn_vk_status <model>_vk_run(
    <model>_vk_context *context,
    const float *input1, size_t input1_elements,
    float *output1, size_t output1_elements,
    char *diagnostic, size_t diagnostic_capacity);

ncnn_vk_status <model>_vk_destroy(<model>_vk_context *context);
```

The generated model-specific header uses one typed pointer/count pair per input and output. Static shape/rank/element-count macros describe continuous FP32 host buffers; callers provide exact element counts to `run`, which has no dynamic shape parameters. The current `ncnn-compile` product subset has one input and one output. The CPU ABI remains a separate stateless API and is unchanged.

The frozen model ABI contract requires a non-null options pointer and context output, clears `*context` before work, and on create failure releases partial resources and leaves it null. `device_index == NCNN_VK_DEVICE_AUTO` selects the first compatible enumerated physical device; an explicit index selects that enumerated device or fails with `UNSUPPORTED_DEVICE`. One context uses one device; multiple devices are selectable by separate contexts, not combined for one graph. Create owns per-context device/pipeline/resources and uploads model constants once. Each successful run performs the complete host-to-device, dispatch, and device-to-host operation; repeated runs are supported. `destroy(NULL)` returns `SUCCESS`; explicit destroy reports cleanup/device errors through the status return, and after destruction the context pointer is invalid and must not be reused. Callers must externally synchronize destruction with all other uses of that context. Concurrent runs on one live context are serialized; distinct contexts are independent. No context is hidden in a process-global singleton.

A nonzero diagnostic capacity requires a writable non-null buffer. On return, such a buffer is NUL-terminated and may contain a truncated UTF-8 diagnostic; capacity zero disables diagnostics. A failed `run` does not promise output-buffer contents. Status values are stable: `SUCCESS=0`, `INVALID_ARGUMENT=1`, `UNSUPPORTED_DEVICE=2`, `OUT_OF_MEMORY=3`, `DEVICE_LOST=4`, `API_ERROR=5`, and `BUFFER_SIZE_MISMATCH=6`.

The CTest `vulkan-abi-c-contract` remains a generated-header-shaped C contract test using a test stub. The V3 device suite retains its model-shaped test adapter. `ncnn-compile-vulkan-product` is registered when both `NCNN_ENABLE_VULKAN_PRODUCT=ON` and `NCNN_ENABLE_VULKAN_V0_TESTS=ON`; it exercises the generated model header and lifecycle symbols in the packaged DSO and requires the configured device/ICD test environment. The standalone product support can be built without enabling that device-test suite. `ncnn-compile` emits the distinct `<model>_vulkan.h`, `<model>_vulkan.json`, `<model>_vulkan.plan.json`, and `lib<model>_vulkan.so` artifacts.

## Product model library and deployment

`--backend=cpu` remains the default. A compiler configured with `NCNN_ENABLE_VULKAN_PRODUCT=ON` accepts explicit `--backend=vulkan`; CPU tuning/thread/vector/ISA flags, dynamic input-shape options, custom clang/linker arguments, CPU-stage emission, and profiling are rejected for this backend. The host toolchain must target 64-bit x86 Linux ELF; the device target remains the independent `vulkan1.1-spirv1.0` target. The backend requires MLIR 21's Vulkan runner pipeline plus `spirv-val` and `spirv-dis` at build/run time. The default CPU-only CMake configuration does not enable Vulkan product dependencies.

The product path currently accepts a complete static FP32 single-ReLU graph with one input and one output. Ranks 1–4, positive static extents and the 128 MiB storage-buffer limit are checked. Other operations—including Add, Conv, or multiple pointwise operations—dynamic extents, non-FP32 data, and unsupported layouts fail before publication even where an individual operation is supported by the V2 lowering pass. There is no CPU fallback.

The driver embeds the validated SPIR-V and deterministic schema-v1 plan in the model DSO. The manifest records plan/shader/`.param`/`.bin` hashes, host/device targets, public I/O and the DSO's actual `DT_NEEDED` entries. The library exports only `<model>_vk_create`, `<model>_vk_run`, and `<model>_vk_destroy`; it has no RPATH/RUNPATH to the compiler build or temporary directory. Deployment must provide the manifest-listed LLVM 21 shared runtime, Vulkan loader, system C/C++ runtime, and a compatible Vulkan 1.1 device/ICD. The generated header includes the public `ModelABI.h` contract installed by the compiler package.

`--verify-execution` makes `ncnn-compile` `dlopen` the staged DSO, create a Vulkan context, run a deterministic ReLU buffer and check its output before publication. Device absence or runtime failure fails the requested verification and leaves prior output intact. Without this flag, compilation performs offline SPIR-V validation but does not require creating a device. CPU and Vulkan default output directories are separate; explicit output directories containing artifacts from the other backend are refused. Publication of header, plan, manifest and library uses the same staged sibling-directory replacement and rollback transaction as CPU artifacts.

## Standalone Linux host runtime

`include/ncnn-mlir/Vulkan/VulkanRuntime.hpp` and `lib/VulkanRuntime/` implement the V3 host execution core. `VulkanRuntimeContext::create` takes a typed schema-v1 plan, exactly one `(kernel ID, SPIR-V words)` payload per planned kernel, weight payloads keyed by resource ID, and runtime options. The runtime verifies the plan, binary IDs/magic, resource sizes, weight IDs, and plan weight SHA-256 identities before dispatch setup. Shader and weight payload spans are consumed synchronously by `create`; their backing storage may be released after it returns. Physical weight payloads must match the plan's physical layout; for the implemented OIHW→HWCF convolution case the runtime reverses that mapping to verify the plan's logical OIHW identity. Bias identity is checked directly. SPIR-V semantic validation remains an offline `spirv-val` responsibility.

The current host runtime accepts only `device_target = "vulkan1.1-spirv1.0"`, static FP32 storage buffers, and one-dimensional workgroups `[x,1,1]`; device-specific workgroup, descriptor, push-constant and storage-buffer limits are checked during create. Each storage buffer is limited by both the plan's 128 MiB minimum-range contract and the selected device's actual `maxStorageBufferRange`. The default aggregate context allocation cap is 512 MiB. It counts actual Vulkan memory requirement sizes for every device resource, persistent public-I/O staging buffer, and temporary weight staging buffer during upload; exceeding the cap fails create with `OUT_OF_MEMORY` before Vulkan memory allocation. No resource aliasing is performed. `get_device_info()` reports the selected physical-device name plus Vulkan API/driver versions and vendor/device IDs; the optional device-name match filter is test-only and is not part of ABI v1.

Each context owns its Vulkan 1.1 instance, selected physical/logical device, compute queue, one reusable command pool/buffer/fence, per-resource device buffers, descriptor sets/layouts, shader modules and compute pipelines. Create is transactional: `*context` remains null on failure, and all successfully created Vulkan handles are released in reverse dependency order. Static weight and bias resources are staged and uploaded once during create. Every run copies caller input bytes to mapped host-visible staging, flushes mapped writes when required, records host→transfer and transfer→compute barriers, dispatches kernels in plan order, inserts compute write→compute read/write barriers for inter-kernel resource hazards, copies outputs to readback staging, applies transfer→host synchronization, waits on the reusable fence, invalidates mapped reads when required, and only then copies bytes to caller outputs. Buffer copy offsets are zero and all FP32 byte counts are four-byte aligned. Staging mappings cover the full allocation and flush/invalidate use `VK_WHOLE_SIZE`.

`run` requires exactly one non-null byte span of exact `byte_size` for each public input and output resource; caller memory must remain valid until `run` returns. A run failure does not promise output contents. Errors map to the stable ABI status set: host/device/descriptor allocation failure→`OUT_OF_MEMORY`, device lost→`DEVICE_LOST`, unsupported device/target/limits→`UNSUPPORTED_DEVICE`, size mismatch→`BUFFER_SIZE_MISMATCH`, malformed package/options→`INVALID_ARGUMENT`, and other Vulkan failures→`API_ERROR`; diagnostics are bounded and NUL-terminated at the C ABI fixture boundary. A context whose dispatch submission/wait fails is marked unusable; destroy it and create a new context before retrying. Explicit destroy reports device-idle or validation-layer cleanup errors before releasing the context. Calls to one live context are serialized, including command-pool and queue access; separate contexts own independent mutable resources. Callers must synchronize destroy against every other context use.

The runtime library is configured when either `NCNN_ENABLE_VULKAN_PRODUCT=ON` or `NCNN_ENABLE_VULKAN_V0_TESTS=ON`; Vulkan build dependencies remain absent from the default CPU build. The V0–V3 device-test option requires a Vulkan loader/headers, SPIR-V tools, the Khronos validation layer, and configured software/real-device ICDs. `test/Vulkan/vulkan_runtime_abi_fixture.*` remains a test-only adapter; its fault injector is an in-process test hook and is not a product runtime control.

## Vulkan execution-plan schema

`ncnn-mlir/Support/VulkanExecutionPlan.hpp` defines the separate typed schema, serializer, deserializer, and verifier. It is not the CPU `EmitModelPlan` JSON or the CPU C ABI manifest. The current CPU execution-plan pipeline does not emit this Vulkan schema.

The version-1 JSON kind is `ncnn.vulkan_execution_plan`. Its top-level fields are `schema_version`, `kind`, `model`, `build_identity`, `host_triple`, `device_target`, `resources`, `kernels`, `inputs`, `outputs`, and `plan_hash`. Resources describe a unique ID, role, FP32 static shape/byte size, logical and physical layouts, optional host layout and an optional structured layout transform (`from_layout`, `to_layout`, `operation`; host-to-device for inputs and device-to-host for outputs), optional weight SHA-256 identity, and first/last kernel indices. Kernels are stored in execution order and describe unique ID, operation, SPIR-V entry point, workgroup size, resource reads/writes, descriptor set/binding/access records, and push-constant bytes by offset. Public I/O maps to resource IDs.

The verifier rejects unknown schema versions/JSON fields, duplicate IDs or descriptor locations, malformed weight identities, unchecked/mismatched byte sizes, sizes over the Vulkan 1.1 minimum storage-buffer range, missing host/device layout mappings, invalid workgroup/push-constant bounds, read-before-write, writes to inputs/weights, incomplete descriptor coverage, invalid public I/O roles, and lifetimes that do not exactly cover ordered uses. JSON serialization is deterministic; `plan_hash` is the 16-digit lowercase hexadecimal `stableHash64` of the canonical plan JSON with the `plan_hash` field omitted. Deserialization validates the stored hash. Kernel schedule records are verified with synthetic unit fixtures; this schema alone does not create executable shaders, Vulkan resources, or dispatch code.
